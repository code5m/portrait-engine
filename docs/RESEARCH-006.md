# Research 006：让面部体面接受同一束光

**研究目标**：不是扩建编辑器，而是验证：眉骨、眼窝、颧骨、鼻翼、下颌可以由一套共同的明暗规则控制吗？为什么上一版看起来像塑料面具？

## 1. 研究假设

Research 005 虽能修改眼睑与口角，却仍把许多局部阴影分别手工配置。侧光移动时，面部各块的明暗不总是具有一致的空间解释，导致五官像悬浮在脸上。此次用一套**明确、可测试的近似法线模型**替代新增实验层的独立明暗配置。

本轮不是人体扫描、不是三维重建，也没有真实漫反射/次表面散射。所谓「体面」只是**按面部区域分割、赋予手绘近似法线的二维 CSS 图层**。

## 2. 本次原创实现

- `src/volume.mjs`：12 个体面的法线，共享一个方向性光源，导出可审查的无 DOM 数值契约 `deriveVolumeStyle()`。两个脸颊、两侧眉弓、两侧眼窝、鼻翼及下颌使用相同的光照计算。
- `index.html`：面部增加 12 个仅在实验中显示的独立 CSS 体面元素，均为普通 HTML 节点。
- `styles/study006.css`：柔和的体面暗部、局部顺形体排线及虚化边界。**禁止** `url()`、图片、SVG、Canvas、纹理文件或 AI 人像。
- `?r006=volume`：显式启用实验。`?r006=baseline`：同参数基线。实验不写入用户现有 JSON 或浏览器本地角色存档；公开默认仍为 Research 004 原始绘画。
- `study/006-compare.html`：在两栏中呈现同参数的 CSS 对照。它**不是匿名盲评**，不能产生人类偏好的结论。
- `standalone.html`：由唯一构建脚本重建，完全离线；源码和打包结果走同一组测试。

## 3. 观察与证据

运行 `npm run verify`，再运行：

```bash
python3 -m pip install playwright pillow
python3 -m playwright install chromium
python3 test/browser-qa.py
python3 test/study005-visual.py
python3 test/study006-visual.py
```

自动验证包括：

- 80%、100%、120% 三种脸宽与 -60°、0°、+60° 三种光照，针对**基线和实验两种绘画方式各九张**，共 18 张 Chromium 渲染图。
- 两侧眉骨/眼窝/脸颊/鼻翼/下颌在相反光源下的明暗序关系、前光时的对称性。
- 固定的人脸参数格式保持 9 项；旧版只含 7 项参数的 JSON 仍可导入，不加「实验状态」字段。
- DOM 中仍不含 `<img>` / `<svg>` / `<canvas>`；手机端无水平溢出；JS 控制台无未捕获错误。
- `test-results/research-006/contact-sheet.png` 和 `observations.json` 为**测试过程中生成的证据**，不参与最终网页的绘画。

本地 Chromium 运行在受限容器内，测试脚本先尝试同源 HTTP，失败后会退回内联的、与仓库 `standalone.html` 相同的代码。这不等于已完成多设备全浏览器兼容验证；GitHub Actions 应以远端运行日志为准。

在一轮本地渲染中，同光向 100% 脸宽的 A/B 整页 RGB 差异均值约为 **(0.85, 0.85, 0.85) / 255**。它只能证明实验确实改变了像素；**数值既不代表性能提升，也不代表美术质量提升**。两帧 `requestAnimationFrame` 采样还包含帧等待时间，不能被解释为 GPU 绘制耗时或浏览器性能结论。

## 4. 发现：统一光照不等于自然人脸

实际渲染能看出眼窝、鼻侧、下颌局部的明暗反应更协调，但根本缺陷仍然明显：

- 鼻梁仍偏独立的亮柱，**鼻尖到颧骨之间的形体过渡还不真实**。
- 左右头发依然是较硬的块状剪影，局部发丝有重复式样。
- 眼白、虹膜、上下眼睑之间尚未构成足够自然的真实眼窝深度。
- 所有体面位置仍由二维坐标手工锚定；没有对头骨几何与遮挡建立统一的可变形规则。

**裁决：Research 006 是可复现的结构/光照实验，艺术质量未知，不自动替换默认作品。**

## 5. 下一轮方向与可证伪要求

1. 将眼窝、鼻梁和颧骨的锚点由现在的独立绝对坐标迁移到相互依赖的面部结构参考系，并测试宽脸/窄脸时的偏移。不能靠更长 CSS 背景覆盖遮羞。
2. 邀请至少三位互不知情的独立观察者在固定条件下判定 A/B 的人脸可信度，保留原始评分。无外部评分时，状态保持 `UNVERIFIED`。
3. 若模型只制造更深阴影而不能提升可信度，则**回退或保留为实验**；明确记录程序化二维绘画的限制。允许在隔离分支研究 SVG，但绝不把 SVG 结果冒充「纯 CSS」。

> 项目研究原则：先让作品成立，再证明技术本身有多强。每次做出可被反证的改进，而不是给已有形状不断追加装饰。
