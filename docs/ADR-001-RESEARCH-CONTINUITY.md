- 决策日期：2026-10-14
- 状态：研究方向约束（不代表新技术已经发明或实施）
- 唯一主仓库：`code5m/portrait-engine`
- 现有稳定主线基准：Research 006，提交 `bdc7f29d0add4d090bcb415912e8a5e69d6ea7c5`
- 下一项实施任务：Research 007（Issue #3）

## 为什么有这份记录

Portrait Engine 起源于一个严格实验：**不使用图像、SVG、Canvas 或 AI 生图素材，由 HTML 元素与 CSS 原生绘制形状构成人物肖像。**
后续讨论的“Portrait Structure Language / PSL（可编程肖像结构语言）”目前**只是待验证的研究假说**，不是已经实现的新技术，也**不取代、否定或删除前六轮成果**。

长期理想始终是：用少量语义明确的结构表达人物，让肖像可理解、可精确编辑、可复现；作品的可信度与艺术质量优先于技术表演。

## 架构决策：先验证共享人脸结构，再谈语言

```text
Portrait Engine（同一仓库，历史成果保留）
  Existing v1 JSON parameters（兼容，不强制升级）
                   |
        FaceGeometry / FaceModel（Research 007，待验证）
                   |
       +-----------+--------------------+
       |                                |
  CSS Renderer（原创实验主线）    Possible Alternative Renderers（尚未实施）
       |                                |
  HTML / CSS 笔触、体面和光影       SVG / Canvas / WebGL 必须隔离并明确标示
       |
  standalone.html + 真实浏览器测试
```

1. **保持 CSS 实验的可运行性。** 当前 `index.html`、`styles/*.css`、`standalone.html`、参数 JSON 导入导出和 GitHub 两类 CI 是资产，不得为了 PSL 概念而删除、覆盖或更名。
2. **只重构有证据的问题。** 优先执行 Research 007：共享眉弓、眼眶、鼻根、颧骨、口角、下颌的局部坐标；使至少眼窝、鼻部、下颌使用同一套推导数据，而不靠多个互不相关的绝对坐标。
3. **PSL 不先于模型成立。** 在真实可复用 FaceGeometry、明确数据版本协议、可运行结构变形和视觉对照结果出现之前，PSL 仅作为工作名称/研究假说，不建独立框架，不宣称发明。
4. **渲染器允许并存，但不能偷换实验定义。** 如果 SVG 或 WebGL 后端被验证有价值，作为单独命名的研究候选增加；严禁将它伪装成“纯 CSS 绘画”。同一人物结构可以用于多个后端，但原生 CSS 基线始终可独立运行。
5. **建立回退和可信证据。** 新绘制方法先作为 opt-in 实验，不静默改变用户保存的人物；使用相同人物参数、宽度/光照组合采集浏览器证据；至少三位独立真人观察者评分之前保持 `ART_UNVERIFIED`。如果艺术效果和维护成本不符合预期，维持原版、不强行推广。

## 明确当前未完成事项

- 尚未建成解剖一致的人脸共享结构模型（Research 007 进行前）。
- 未实现“一套结构生成十个可信独立人物”，身份一致性尚未验证。
- 未获得独立真人对照评分或专业写实质量验收。
- PSL 没有被设计为可用语法、编译器或新格式；不得将本文当作已实现证明。
- 既有仓库继续是单一事实源；禁止新建一套不兼容的重复肖像工程。

## 研究路线闸门

**第 1 关：** Research 007 形成可测试 FaceGeometry，与已有 CSS 渲染和九项参数完全兼容。

**第 2 关：** 相同身份在不同脸型、光照及面部表情下，获得几何、交互和主观视觉证据；公开失败案例。

**第 3 关：** 如果跨渲染器共同表达结构确有收益，才提炼小型、可版本化的 Portrait Structure 数据协议，再考虑是否值得称为 PSL。

所有关卡必须保留前六轮源代码、研究报告、测试和单文件产物；任何“更真实”结论必须由真人评价支持，而不是由工程测试替代。
