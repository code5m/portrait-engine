# Research 008 — 从共享骨相到连续表面明暗：结构能不能真正指导素描？

## 假设

Research 007 的 16 个面部锚点控制了器官和阴影的位置，但 R006 的 12 个体面法线依然是固定的。**改变下颌或鼻翼宽度时，器官已经移动，光照法线未跟随形态变化。**

本轮设计一个实验性的、连续的 2.5D *Relief Field*：用 R007 的相同锚点定义正负高斯起伏（眉弓隆起、眼窝凹陷、鼻根和鼻底、鼻翼、颧骨、颊颌过渡、口周和颏部），用有限差分估算每个观察点的单位法线，借用 R006 的统一光照方向产生明暗。鼻下软投影使用鼻底位置与反向光源位移；颊部排线使用颧骨到下颌的切线。

核心不只是多添加 CSS：**参数 → 共享结构 → 连续高度梯度 → 同一光源明暗 → CSS 原生素描。** JS 仅计算绘画参数、不操作图片像素。此模型不是真实头骨、纹理笔刷或物理阴影，不能宣传成通用 3D 头像。

## 可运行的两组对照

| 方案 | 同一人物结构 | 光照 | 笔触与软投影 |
| --- | --- | --- | --- |
| `?r008=legacy` | R007 结构化锚点 | R006 固定法线 | 原有排线/无新增鼻下投影 |
| `?r008=field` | **同一套** R007 锚点 | R008 局部浮雕梯度法线 | 颧骨—下颌切线排线、随光源变化的鼻下软投影 |

原本默认的 9 项参数肖像、前七轮研究与 `standalone.html` 完全保留。实验不触碰 localStorage、角色 JSON v1，支持原先只含 7 项参数的存档。实验页面：`study/008-compare.html`，不是盲评，只是公开 A/B。

## 研究过程中的真实失败与修复

最初新增 `src/surface-field.mjs` 时定义了与 `src/volume.mjs` **同名**的顶层 `const clamp`。虽然各个 `.mjs` 文件语法合法，离线打包器删除 `import/export` 后将其合成一个 JS 模块，触发 `Identifier 'clamp' has already been declared`，浏览器画面不能初始化。这是**本轮真实发现的构建架构风险**，不能只修复个别变量名后忽略。

现统一使用局部 `clampField`，同时新增 `scripts/check-standalone.py`：每次 `npm run verify` 都提取最终独立 HTML 内联 JS，实际运行 `node --check`。这是新增的**长期防退化门禁**，以后模块新增时不再靠人工碰巧发现。

## 视觉自查结论

并排观察显示，浮雕场在眼周、鼻根与颊部创造了更明显的共同明暗，但也让部分眼窝变得更暗、鼻侧产生更浓的高斯阴影；有**变得更像面具或塑料浮雕的风险**。结构联动得到工程验证，**艺术可信度不能宣布胜出**。

独立真人盲评仍为 **0 份**；视觉质量状态保持 `ART_UNVERIFIED`。后续应固定参数随机分配匿名图，让至少三名外部观察者比较眼窝、鼻部体积和整体自然度，再决定是否保留新方案。如没有进步，记录失败并回退，而不是无限累加绘画装饰。

## 对长远“可编程肖像结构语言”研究的意义

本轮新增一个**可推导的连续表面光照候选**，为未来跨渲染器共享人物形体提供实验数据，尚不是 PSL 语法、可泛化的身份生成器，也没有独立证明任何新技术原创性。PSL 继续作为研究假说，依照 `ADR-001` 的实施门槛推进。
