# Research 009 — 基于共享面部法线的铅笔排线，能否替代一部分塑料浮雕阴影？

**状态：`ENGINEERING_PASS / ART_UNVERIFIED`。** 研究仓库：`code5m/portrait-engine`，以 GitHub `main` 最新提交及双 CI 为最终工程判据。

## 研究问题

Research 008 将 R007 的面部锚点转换成连续起伏表面，并用 R006 同一个光源控制眼窝、鼻根、颊部、颌部的明暗，但实际截图显示脸部仍像**模糊渐变组成的面具**。这次不是再给眼睛增加两层效果，而是提出一个可否定的研究假设：

> 在保持完全相同的面部锚点与浮雕场的前提下，把部分连续模糊阴影换成沿表面等高线走向、深浅随光源调节的干铅笔线，能否让素描具有更多“纸上的形体笔触”感？

**结果不能通过代码测试决定**。至少需要外部观察者、相同人物与光照条件下的匿名对照；这轮只交付实验候选及可复现证据。

## 可检查的算法

- `src/stroke-field.mjs` 重用 `deriveSurfaceField`，使用 R008 同一表面法线、光源和 `--v-*shade` 值，不发明第二套不兼容的人脸模型。
- 对眼眶、眉骨、鼻翼、颊骨、下颌及颏点共 **11 区域**计算：
  - `angle = atan2(-nx, ny)`，归一到 `[0,180)` 度：梯度变化方向确定画线等高线的切向。它只依赖人脸几何，不因光照方向变化而乱转。
  - `opacity = clamp((shade − 0.16) × 0.68, 0, 0.39) × hatching / 100`：受光面接近纸白，背光面加重线条。
  - 位置由 `--fg-...` R007 共享解剖锚点确定，不用 fixed 或复制另一套绝对脸部坐标。
- `styles/study009.css` 使用原生 CSS `repeating-linear-gradient` + `mask-image` 形成条纹。JavaScript 只生成数字，不绘制图像像素；**没有 `<img>`、SVG、Canvas、AI 生图、CSS `url()` 素材**。
- `src/app.mjs` 仅在 `?r009=strokes` 时计算新自定义属性。实验页不写入旧的 9 项参数存档；7 项旧版本仍可导入。单文件构建器仍将所有艺术代码内联到 `standalone.html`。

## 视觉自查与失败证据

对比截图 `test-results/research-009/contact-sheet.png` 及 `face-close-comparison.png` 显示：新的笔触在眼下、颊部出现细而短的暗纹，受光侧更轻、背光侧更重；但在缩小到正常观看尺度时变化**很微弱**。人物仍有“黑色头发壳、规则眼白、几何颊骨、塑料浮雕”的明显不自然感。添加少量排线不能解决根本的身份可信度问题，也有制造新机械纹理的风险。

这次不能宣称新版本获胜；**独立真人盲评：0 份；写实质量：未达标。** 候选默认保持 `tonal` 旧画法，仅供复现实验。

## 下一轮必须面对的研究选择

请至少邀请 5 名外部观察者，在相同光向、五官参数和分辨率下盲选 A/B（至少 2–3 组参数）。统计分数和信心区间，而不是只看是否“有像素差”。如果大多数观察者选择平滑版或无明显偏好，应将 R009 标注为 **不提升美术质量**、停止继续堆纹理，回到脸部大形 / 眼窝比例的结构重新设计。独立于 CSS 的 SVG 绘制对照如需展开，应作为另一渲染器明确隔离和标注，不能冒充纯 CSS。

**最终研究理想：浏览器成为可解释、可改变的视觉表达媒介，而不是靠工程绿灯去证明一张面具已变成真人。**
