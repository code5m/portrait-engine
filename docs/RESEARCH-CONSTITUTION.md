# Portrait Engine — 研究宪章与不可绕过的质量约束

> **研究的是通用生成能力，人物作品是验证手段，写实质量是核心衡量标准。**

本规范高于任何单张画像效果、单次参数演示、界面功能数量与 CI 绿灯。目标是探索：**HTML + CSS 是唯一人物绘制媒介，JavaScript 仅负责计算与交互**，能否持续生成不同人物且具有可信的人体结构与越来越高的视觉写实度。任何实验允许失败，但失败必须记录，不能包装成成功。

## 一、三个不同层次的交付物

1. **通用生成引擎**：统一 Face DNA → Geometry → Form/Volume → Lighting → Surface/Hair/Expression → CSS renderer；新人物仅调整参数与配置，不为每个身份追加手工画脸 CSS。
2. **人物作品和实验矩阵**：至少 3 个不同身份 × 3 种光照 × 5 种表情共 **45 个场景/模式**；产生原生 Chromium 浏览器帧和机器可读取的实验清单。每次研究保留未改动的控制组，禁止只选最好看的一张。
3. **写实质量证据**：解剖、立体感、皮肤/发丝、眼睛、表情、身份辨识、泛化；主要依赖可复现的独立盲评数据而非代码行数、可变参数数量、像素差或 AI 自评分。

## 二、三种完全不同的“通过”

| 门禁 | 自动化可认定 | 自动化不能认定 |
|---|---|---|
| `ENGINE_PASS` | 兼容、可重复、变量有限、身份参数可区分、材质限制、禁止硬编码、构建同步 | 真人解剖自然/像真人 |
| `RENDER_PASS` | Chromium 真的画了 3×3×5 场景、无外部图片请求、前后版本像素/样式签名符合实验约束、默认图不被偷偷换掉 | 作品比较好看/达到写实 |
| `ART_VERIFIED`（需要人） | 只可自动检查独立观察记录的结构、覆盖度和计算，不能验证来源真实性 | 不能由单元测试、AI/机器打分、GitHub Actions 或零真实观察者自动生成 |

**工程 PR 可以合并实验代码但必须 opt-in；没有人工艺术证据不能把候选设为默认，也不能宣称写实质量合格。** 本门禁的“默认稳定”比较以当前 `main` 的真实默认画面为基线。历史上 R005–R009 部分效果已进入 V1 默认复合画面，不能再虚称从未启用；R012/R013 仍需显式激活。

## 三、原生绘制媒介与边界

- `HTML` 仅组织人脸 DOM；`CSS` 通过边框、形状、渐变、遮罩、阴影绘制。JS 输出数值、几何、字段、CSS 自定义属性，负责交互、参数编解码；不得通过 JS 逐像素绘制或加载图片再贴到人物。
- 在 **人物渲染链路** 中禁止 PNG/JPG/WebP/GIF、SVG、Canvas、WebGL、WebGPU、video、bitmap、远程图片、CSS `url()`、`image-set()`、`@import`、Houdini `paint()`。测试生成的截图是**评价证据**，不得作为渲染输入或提交为运行时素材。
- 新实验的 CSS 必须有专属 `[data-rNNN=...]` 选择器及显式 URL 查询开关；不得出现针对预设 `data-identity`/人物 id 的特判画脸。
- 禁止无关模块复制面部几何计算；同一批次渲染不要重复运行整个 `deriveEngineStyle`。
- 不改变旧人物文件协议或旧版页面语义；如需迁移，先做明确版本与兼容性测试。

## 四、实验登记与失败纪律

`research/experiments.json` 是研究状态台账。新编号 R014、R015……至少记录：假设、可证伪标准、基线、独立候选开关、评价矩阵和真实状态。命名为 `researchNNN.css` 或添加新的 `?rNNN=` 模式，必须先登记。

- `ART_UNVERIFIED`：工程可完成，艺术质量仍未知。
- `REJECTED_FIRST_VIEW`：研究员基于视觉样张发现明显问题，尚未取得独立盲评。
- `PROMISING_NEEDS_REPLICATION`：达到事先声明的人工评审门槛，尚需不同样本复核。
- `ART_VERIFIED_WITH_INDEPENDENT_EVIDENCE`：已附正式多身份、多条件评审数据；**不能仅靠 GitHub CI 声称达标**。

**失败研究留在历史并写明原因**；不合格候选不升级默认。新研究必须避免用统一脸模板+少量滑块冒充通用身份生成。

## 五、未来 PR 与发布的检查顺序

1. **静态/安全与协议**：`npm run verify`、`npm run governance:check`，审查人物 DOM、CSS 载图入口、非法绘制 API、实验是否 opt-in、研究台账及默认状态声明。
2. **跨身份与光影的模型一致性**：至少三份独立 DNA，三种光照、五种表情，不得抹掉身份锚点；同一身份换光时轮廓不变，换表情时 Face DNA 不变。年龄、头发、皮肤只能认定为“已实现”若 DOM 视觉受控并经实测。
3. **真实浏览器质量矩阵**：Chromium 截图 + 结构签名 + 非空画面 + 外部图片/画布请求检查 + 错误检查 + 默认渲染与 PR 基线截图对比。亮暗与像素差只代表技术变化，不代表变美。
4. **评审/晋升**：有独立观察者的匿名随机 A/B 证据。至少 5 位独立成年观察者；至少 3 身份×3 灯位×2 表情的成对场景，记录整体真实感、解剖、体积、皮肤与头发、眼睛与表情、身份辨识、泛化。≥75% 观察者整体偏好候选、真实感中位差至少 +1，核心几何/身份不能退步，才可能达到 `PROMISING_NEEDS_REPLICATION`；需独立复现后再考虑 `ART_VERIFIED`。即使评分结构完整仍需人复核观察者真实性。
5. **默认变更门禁**：PR 和 `main` 基线 3×3 中性表情浏览器像素对照。如果默认像素发生改变且没有完整的人工评分证据，阻止误升默认。只针对候选专属开关生效的改动允许工程性合并。美术主观结论由人裁决，门禁不可自动伪造 `ART_PASS`。
6. **成本**：记录 DOM 数量、浏览器场景耗时与 screenshot 清单。对性能回归设置基线前不得凭一次 CI 噪声给性能“提升”结论。

执行 `npm run verify` / `npm run governance:check` / `python test/research-governance-matrix.py`。合并检查以 GitHub Actions 同一 PR commit 为准，不能用旧分支绿灯替代最新修改。
